Memory recall, IDF-ranked

self_seed.py:65 · memory_self_seed() → index.py:35 · rank_promotions()

G0 matches the global index by the seed's tokens, then hands the candidates to the ranker instead of taking the first N alphabetically.

def rank_promotions(graph, queries, *, prefixes, max_seeds, exclude, hub_ratio=0.4):
    suppress_hubs = len(graph.nodes) >= 20          # saturate first, then penalize
    for q in queries:
        df = len(match_index_nodes(graph, q))
        if suppress_hubs and df / N > hub_ratio: continue  # drop hub token
        idf = math.log(N / (1 + df))              # rare → high score
        for node in hits: scores[node.id] += idf
B4 a generic hub token that matches a large share of a big index is suppressed, so a saturated domain can't be recalled for an unrelated seed — IDF rarity IS the per-domain cap

The crawl — a bounded, concurrent frontier

loop/crawl.py:23 · crawl()

Seed + promoted extras go on a depth-0 frontier; each level is fetched concurrently, distilled, and persisted, bounded by depth / max_nodes / max_seconds. Fetch failures become declared gaps, never dropped.

frontier = [(normalize_seed(s), 0) for s in [seed, *extra_seeds]]
while frontier and len(visited) < max_nodes and elapsed < max_seconds:
    fetched = await asyncio.gather(*(fetch(nid) for nid …))
    note.run_id, note.depth = run_id, d          # B0 invariant: run_id == context_id
    if d < depth: frontier += in-scope links (d+1)
B0 every note is stamped run_id = context_id here — the key that lets refine later scope to this run's own nodes

Inside one round · the exact sequence

while rnd < max_rounds — explore/loop.py:190

Blue = deterministic step · amber = de-bias hook. Order matters: pruning happens before the reference is frozen, so rejected nodes never pollute the anchors.

  1. EXPAND — run expansion_round (round 0 passes thin/parent; later rounds are terse, focus-only) :196
  2. B2 · carry — a dev-panel codegraph queued last round is prepended to new_seeds so it leads the crawl :206
  3. B5 · gate — if rnd>0: keep only promotions that graph_grounded() to the frozen seed graph :210
  4. CONVERGE? — rounds >0 with nothing new to explore → stop :220
  5. CRAWL — round 0 crawls seed + extras; later rounds crawl only the promoted set, under a per-round sub-budget :234
  6. B6 · prune — drop crawled notes whose title matches a rejected token, mark them visited, BEFORE accumulate :245
  7. ACCUMULATE — merge the round's nodes into the result, cross-round dedup via visited :254
  8. B2 · anchor — (re)derive code-vocabulary tokens from any codegraph note's synopsis :258
  9. B2 · auto-resolve — round 0 only, opt-in: queue one dev-panel repo into carry :264
  10. B3 · freeze — round 0 only: extend seed_ref with the round-0 neighborhood titles… :272
  11. B5 · freeze — …and set seed_anchor_ids = round-0 node ids + their link targets :277
  12. CONVERGE? — no new nodes → marginal yield exhausted → stop :281
  13. B2 + B6 · focus — next focus = anchor tokens lead, then fresh title tokens, minus any excluded tokens :290
  14. B3 · coherence stop — score the next focus vs seed_ref ∪ anchor; too few shared → drifted, stop :304
  15. SAVE — persist round, focus, anchor, carry, ref, anchor_ids, exclude → resume-safe :321

Why this order? B6 prune (step 6) runs before the B3/B5 freeze (steps 10–11) so a rejected cluster never enters the coherence reference or the seed graph. And B3 scores distance from the frozen seed reference, never the growing pack — that's what stops round-2 drift from compounding on round-1's additions.

Worst-case drift · B3 firing in production

A real run of the field-case thin seed. Without B3 this is the memory-bias gravity well: round 1 admits some off-topic nodes, round 2 anchors on them instead of the seed, and the well deepens. B3 scores each round's next focus against the frozen seed reference — and pulls the emergency brake the moment the overlap hits zero.

ref = seed_ref | set(anchor.split())

if min_coherence and ref and shared < min_coherence:      # 0 < 1

Contrast — the same seed without an off-topic round converges normally: the baseline run (no drift) ended round 2: promoted=0, new nodes=0 → converged. So the two stop conditions are distinct and both reported: converged (on-topic and dry) vs off-seed drift (wandered). That distinction — "convergence = on-topic AND dry, not merely no new nodes" — is exactly what B3 adds.
