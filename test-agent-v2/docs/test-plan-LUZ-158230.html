Methodology

Approach
Mostly API-level testing against luz_docs_import's import pipeline and the document-metadata read contract, with two UI-level checks. Seven tracks, ~5 API / 2 UI.
Equivalence Partitioning + Boundary Value Analysis
Applied field-by-field and rule-by-rule (required fields, string lengths, ID formats), with pairwise added where fields interact — chiefly documentTypes=HEALTH × presence/absence of healthData.
HEALTH decision table
A dedicated table for the documentTypes × healthData × sub-object-completeness accept/reject rules, kept separate from the general sweep for independent review.
Fault-injection (two tracks)
Error-path testing of the import as one logical operation; a second dedicated track for batch-vs-per-document failure semantics and sender/recipient resolution failures.
Risk-based depth
Authorization / ACL / cross-tenant scenarios are risk-critical (health-data compliance) and get full coverage.
Security + i18n
Added now: zip-slip / path traversal, zip-bomb / entry-count / size limits; label encoding and missing-language fallback.
