Confirmed decisions

The scope/methodology/metric decisions locked during refine + define (25 decisions, 0 open gaps). These drive every assertion above.

Definition of done

Fully-materialized end-state: job reaches DONE AND documents/folders/healthData persisted and readable in eArchive — not merely 'accepted'.

Two-layer failure model

Import/ZIP-parse layer: missing/malformed metadata.json or unrecognized documentTypes -> DEFAULT metadata + SUCCESS. luz-docs domain layer: present-but-invalid metadata -> that file FAILED (file by file). Never atomic-whole-ZIP.

Sender identity

OUT OF SCOPE — the service does not validate or route on senderTenantId/senderCompanyId/senderName; they are attribution-only. Recipient travels via the authenticated transport channel.

HEALTH type

documentTypes is an array carried to luz-docs; HEALTH is generic passthrough (not schema-locked in the importer). SNOMED codes + de/fr/it/en labels persisted verbatim; reference value-set validation is LUZ-158241's scope.

Coverage bar

happy + negative + boundary + error, plus security(zip-slip) + performance + concurrency + i18n + backward-compat regression.

Test approach

HIT ALL REAL DEPS — real end-to-end chain luz_docs_import -> luz_antivirus -> luz_docs -> luz_jsonstore (+ Mongo), no stubs; real transfer.zip fixtures per the canonical Fixture Matrix.

Default-metadata rule

When metadata.json is missing/malformed: title == filename minus extension, documentTypes/healthData absent/null (flagged OPEN pending confirmation on the metadata-aware path).

Oracle

End-state / side-effect: assert the stored document + per-file job-report status; for FAILED/negative cases assert NO document created and a consistent end state.
